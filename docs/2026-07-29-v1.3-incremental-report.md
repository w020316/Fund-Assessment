## 3. 问题修复记录

### 3.1 [P3] data_source_v2.py 缓存注释与实现不符

- **问题描述**: `_cache_set` 注释称"LRU 淘汰",但实现是 FIFO(删最早插入条目,不在读取时更新访问顺序)
- **修复方案**: 修正注释为"FIFO 淘汰"并说明实时行情场景下命中率与 LRU 接近
- **修复状态**: ✓ 已修复([src/core/data_source_v2.py#L63-L64](file:///d:/xm/wz/Fund-Assessment/src/core/data_source_v2.py#L63-L64))
- **影响**: 无功能影响,仅注释准确性提升

### 3.2 [P3] ai_service.py 4 行死代码常量

- **问题描述**: `_TTAPI_API_KEY`/`_TAVILY_API_KEY`/`_TINYFISH_API_KEY`/`_AGNES_API_KEY` 4 个模块级常量在 b3e2a99 后无任何使用点(全仓 grep 确认),全部已迁移到 `_get_*_api_key()` 函数
- **修复方案**: 删除 4 行常量,更新注释说明已统一通过函数获取
- **修复状态**: ✓ 已修复([src/core/ai_service.py#L38-L44](file:///d:/xm/wz/Fund-Assessment/src/core/ai_service.py#L38-L44))
- **影响**: 减少死代码,符合"避免 backwards-compatibility hacks"约束

### 3.3 [P0] Render 生产环境基金重仓股数据全部失效

- **问题描述**: 调用 `GET /api/holdings/161725`(招商中证白酒)与 `/api/holdings/110022`(易方达蓝筹)均返回 `holdings: []`,提示"未抓取到重仓股数据,可能为新基金或债基"。但两者均为知名股票基金,应有重仓股数据
- **根因定位**:
  - 本地直接调用 `fundf10.eastmoney.com/FundArchivesDatas.aspx` 返回 11686 字节完整数据(含 2026Q2 持仓明细)
  - Render Free 实例位于国外,eastmoney fundf10 子域名对国外 IP 封禁
  - akshare 的 `fund_portfolio_hold_em` 底层亦调 eastmoney,同源封禁
  - **结论: 非代码 bug,是部署环境 IP 限制**
- **修复方案**(诊断机制,非数据恢复):
  - 新增模块级 `_last_fetch_reason` 记录最后一次抓取失败原因
  - `_fetch_fund_holdings_em`/`_fetch_fund_holdings_ak` 在失败路径设置具体原因
  - `analyze_fund_holdings` 返回空时新增 `diagnostic` 字段:`{source_unreachable, reason, hint}`
  - 区分"基金无数据披露"(债基/新基金)与"数据源不可达"(环境问题)
- **修复状态**: ✓ 诊断机制已实施([src/analysis/fund_holdings.py#L41-L44](file:///d:/xm/wz/Fund-Assessment/src/analysis/fund_holdings.py#L41-L44), [L495-L520](file:///d:/xm/wz/Fund-Assessment/src/analysis/fund_holdings.py#L495-L520))
- **根因恢复建议**(需用户决策):
  1. **迁移部署位置**: 迁移至国内可访问 eastmoney 的部署环境(如 Sealos/ClawCloud 国内节点)
  2. **配置 TUSHARE_TOKEN**: 启用 tushare fund_portfolio 第三数据源(注意:免费用户可能无该接口权限,需 2000 积分)
  3. **保持现状**: 接受 Render 国外 IP 限制,本地运行验证功能完整性
