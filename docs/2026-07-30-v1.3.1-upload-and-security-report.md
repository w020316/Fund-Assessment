## 1. 新功能：上传文件/图片识别持仓

### 1.1 功能概述

| 输入类型 | 支持格式 | 识别方式 | 准确率 |
|---------|---------|---------|--------|
| CSV 文件 | .csv | pandas 解析 + 列名别名匹配 | 100% |
| Excel 文件 | .xlsx, .xls | openpyxl + pandas 解析 | 100% |
| 图片 | .png, .jpg, .jpeg, .webp | agnes-2.0-flash 多模态 OCR | 100%（4/4）|

### 1.2 技术实现

- **后端路由**: `POST /api/holdings/upload`
  - 鉴权: `Depends(require_admin)` — 需管理员 token
  - 限流: `@limiter.limit("3/minute")` — 保护 LLM vision 调用
  - 文件大小: 10MB 上限（Content-Length 前置校验 + 读后校验双重防护）
  - 列名兼容: 英文（code/name/weight）+ 中文（基金代码/基金名称/持仓比例）+ 券商常见格式
  - 数据清洗: % 符号清理、数字 code 小数点清理（161725.0 → 161725）

- **AI 视觉识别**: `recognize_holdings_from_image()`
  - 模型: agnes-2.0-flash（免费多模态模型）
  - 调用方式: OpenAI 兼容接口（base64 data URI）
  - 超时: 30s
  - 温度: 0.1（识别任务低温度确保准确）
  - 响应解析: 支持 markdown ```json 包裹清理

- **前端交互**: 上传模态框
  - 文件选择: 支持点击选择 + 拖拽（accept 属性过滤）
  - 上传中状态: 禁用文件输入 + 加载提示
  - 结果展示: 表格形式（#/代码/名称/占比）+ 来源标记
  - 一键导入: 识别结果直接写入 `/api/config/user_positions`
  - 前置校验: admin_token 存在性 + 文件大小

## 2. 安全加固：6 个 P1 问题修复

### 2.1 P1-限流装饰器静默失效（根因修复）

**问题**: `web/api.py` 创建了 `Limiter` 实例并注册了异常处理器，但：
1. **缺失 `SlowAPIMiddleware`**：中间件未注册，装饰器不会被拦截执行
2. **装饰器顺序错误**：`@router.post` 先执行，注册原始函数到路由；模块末尾 `_limiter.limit(...)(func)` 只装饰本地变量，不影响已注册的路由函数

**影响**: 所有 `@limiter.limit` 装饰器静默失效，包括：
- `/api/agent/fund_analyze`（3/min，LLM 高成本）
- `/api/agent/analyze`、`/multi_analyze`、`/portfolio_advice`
- `/api/holdings/upload`（3/min，agnes vision OCR）
- LLM 端点可被无限调用，耗尽免费额度

**修复**:
1. 新建 `web/rate_limiter.py`：独立模块持有 `Limiter` 单例，打破循环 import
2. `web/api.py`：`from web.rate_limiter import limiter` + `app.add_middleware(SlowAPIMiddleware)`
3. `web/routes/holdings.py`：`@limiter.limit("3/minute")` 紧贴函数定义（在 `@router.post` 之前）
4. `web/routes/agent.py`：8 个 LLM 端点全部加 `@limiter.limit("3/minute")` + `request: Request` 参数
5. 删除两处模块末尾失效的重新装饰代码

**验证**: 新增回归测试 `test_rate_limit_triggered_after_3_requests`，验证第 4 次请求返回 429

### 2.2 P1-trace_id 输入注入

**问题**: `web/middleware/trace.py` 直接信任客户端 `X-Trace-Id` 请求头，无长度限制、无字符校验

**影响**:
- 含 `\n`/`\r` 的 trace_id 破坏 loguru 日志格式
- 含 `\r\n` 的 trace_id 可注入 HTTP 响应头

**修复**: 新增 `_sanitize_trace_id()` 函数，正则校验 `^[a-zA-Z0-9_-]{1,64}$`（W3C Trace Context 规范），不合法则生成新 ID

### 2.3 P1-文件上传内存 DoS

**问题**: `web/routes/holdings.py` 的 `await file.read()` 先将整个文件读入内存，之后才检查大小

**影响**: 攻击者上传 100MB 文件时，服务端先分配 100MB 内存再拒绝。Render Free 512MB RAM 上几个并发上传即可 OOM

**修复**: 先检查 `Content-Length` 请求头，超过 10MB + 1KB（multipart 开销）直接返回 413，不读 body

### 2.4 P1-LLM GET 端点缺少限流

**问题**: `/api/agent/opinions`、`/api/agent/debate`、`/api/agent/market_outlook` 调用 LLM 但只有默认 60/minute 限流

**影响**: 匿名用户可高频调用 LLM，绕过设计文档承诺的 3 次/分钟保护

**修复**: 三个端点加 `@limiter.limit("3/minute")` + `request: Request` 参数

### 2.5 P1-前端上传缺乏前置校验

**问题**: `handleUploadFile` 未检查 admin_token 存在性、未校验文件大小、上传中未禁用输入

**修复**:
- 上传前检查 `localStorage.admin_token`，不存在直接提示
- 文件大小前置校验（10MB），超过直接提示
- 上传中 `fileInput.disabled = true`，避免重复提交
- 错误响应给出可操作的下一步建议（检查 token/限流/网络）

### 2.6 P1-测试 fixture 限流状态隔离

**问题**: slowapi 限流基于 IP，TestClient 共享 127.0.0.1，连续测试会累积计数导致第 4 个测试起被 429 拒绝

**修复**: `clear_holdings_cache` fixture 增加 `limiter._storage.reset()` 清除限流计数
