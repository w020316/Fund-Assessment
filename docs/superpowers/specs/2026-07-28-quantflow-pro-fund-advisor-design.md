## 1. 产品定位与核心价值

### 1.1 一句话定位

基于消息面+大盘研判+基金重仓分析,为基金投资者提供买卖建议的智能分析平台。

### 1.2 核心用户

偏专业的基金投资者,关注基金重仓股和板块轮动,不满足于看净值,要穿透到持仓底层逻辑。

### 1.3 核心价值主张

1. **穿透式分析**:不只看基金净值,而是穿透到重仓股、所在板块、大盘趋势,从底层逻辑判断基金走势
2. **消息面驱动**:聚合新闻+公告+研报+舆情,用多智能体辩论提炼出对基金的实际影响
3. **建议而非操作**:给明确的加仓/减仓/持有/观望建议+时机判断,但不代用户执行买卖

### 1.4 分析主线

```
消息面(新闻/公告/研报/舆情) ──┐
                              ├──→ 多智能体辩论 ──→ 板块研判 ──→ 基金买卖建议
大盘研判(指数/资金流/情绪) ───┘                    ↓
                                              重仓股影响分析
```

### 1.5 明确不做

- 买卖操作/模拟下单/实盘交易
- 持仓管理(用户在平台外操作)
- 回测/策略编写(股票量化思维,非基金投资者核心需求)

### 2.4 关键架构决策

1. **消息面聚合独立成模块**:统一接口聚合4类消息源,去重后喂给智能体,避免重复抓取
2. **重仓股分析作为基金建议输入**:不独立成页,融入基金建议和板块研判
3. **智能体角色调整**:保留多空辩论框架,角色从"股票分析师"调整为"基金/板块/消息面分析师"
4. **后端保留 SQLite**:状态持久化够用,避免数据库迁移风险
5. **不接实盘交易**:合规风险,仅做分析建议
6. **Redis 仅预留配置**:P1/P2/P3 不实现,后续扩展
7. **NextAuth.js 不实现**:沿用静态Token鉴权,多用户系统是未来扩展

## 3. 核心功能模块详细设计

### 3.1 消息面聚合引擎(新增 — 核心)

统一聚合4类消息源,去重后输出结构化摘要,喂给智能体辩论。

**数据源**:

| 数据源 | 接口 | 覆盖 | 更新频率 |
|--------|------|------|---------|
| 财经新闻 | akshare `stock_news_em` / `news_cctv` | 东方财富+央视 | 实时 |
| 公告研报 | akshare `stock_notice_report` / `stock_research_report_em` | 上市公司公告+券商研报 | 每日 |
| 舆情热度 | akshare `stock_hot_follow_em` / `stock_hot_tweet_em` | 人气榜+讨论榜 | 实时 |
| AI检索 | Tavily API + LLM总结 | 实时检索+智能总结 | 按需 |

**处理流程**:

```
抓取(4源并行) → 去重(标题相似度>80%合并) → 分类(利好/利空/中性)
    → 相关性评分(按基金/板块关键词匹配) → LLM总结
```

**输出结构**:

```python
{
  "hot_events": [
    {
      "title": "事件标题",
      "source": "来源",
      "sentiment": "利好/利空/中性",
      "affected_sectors": ["板块1", "板块2"],
      "affected_funds": ["基金1", "基金2"],
      "summary": "LLM生成的一句话总结",
      "timestamp": "2026-07-28T10:00:00"
    }
  ],
  "sentiment_index": 65,  # 整体情绪指数 0-100
  "key_news": [...]       # 关键新闻摘要 Top 10
}
```

**API 设计**:

```
GET  /api/news/feed          消息面流(支持板块/基金过滤)
GET  /api/news/hot           热点事件 Top N
GET  /api/news/sentiment     情绪指数
POST /api/news/search        AI检索(Tavily+LLM总结)
```

### 3.2 重仓股板块分析(新增)

从基金持仓反推板块机会,作为基金建议的第4信号输入。

**输入**:akshare `fund_portfolio_hold_em`(基金持仓数据)

**分析链路**:

```
基金代码 → 查询最新持仓 → 提取前10大重仓股
    → 关联到行业板块 → 计算板块集中度
    → 重仓股实时涨跌 → 预估对基金净值影响
```

**输出**:

```python
{
  "fund_code": "005827",
  "fund_name": "易方达蓝筹精选",
  "top_holdings": [
    {"code": "600519", "name": "贵州茅台", "weight": 9.8, "sector": "白酒", "change_pct": 1.2}
  ],
  "sector_distribution": [
    {"sector": "白酒", "weight": 28.5, "trend": "偏多"},
    {"sector": "医药", "weight": 15.2, "trend": "偏空"}
  ],
  "concentration_index": 65,  # 集中度指数 0-100
  "net_value_impact": 0.35    # 预估当日净值影响 %
}
```

**API 设计**:

```
GET /api/fund/{fund_code}/holdings    基金重仓股详情
GET /api/fund/{fund_code}/sectors     板块分布与趋势
```

### 3.3 大盘研判(增强)

新增"大盘温度计"量化指标,作为基金建议的第5信号。

**维度**:

| 维度 | 指标 | 数据源 |
|------|------|--------|
| 指数趋势 | 上证/深证/创业板/科创50 | 6源降级 |
| 板块轮动 | 行业板块涨跌排行/概念热度 | akshare |
| 资金流向 | 北向资金/主力净流入 | akshare |
| 市场情绪 | 涨跌家数/涨停跌停/换手率 | akshare |

**大盘温度计算法**:

```python
temperature = (
    index_trend_score * 0.30 +      # 指数趋势(多头/空头/震荡)
    sector_strength_score * 0.25 +   # 板块强度(上涨板块占比)
    capital_flow_score * 0.25 +      # 资金流向(净流入)
    sentiment_score * 0.20           # 市场情绪(涨跌家数+涨停)
)
# 0-40: 熊市(空头), 40-60: 震荡, 60-100: 牛市(多头)
```

**输出**:大盘温度计(0-100) + 趋势判断 + 板块强弱排行

**API 设计**:

```
GET /api/market/temperature    大盘温度计
GET /api/market/sectors        板块轮动排行
GET /api/market/capital        资金流向
```

### 3.4 基金建议引擎(增强 — 五信号融合)

在原三信号基础上扩展为五信号:

| 信号 | 来源 | 权重 | 说明 |
|------|------|------|------|
| 技术面 | 基金净值趋势/均线 | 20% | 原有,保留 |
| 基本面 | 基金规模/经理/评级 | 20% | 原有,保留 |
| 消息面 | 消息面聚合引擎 | 25% | 新增,权重最高 |
| 重仓股板块 | 重仓股板块分析 | 20% | 新增 |
| 大盘环境 | 大盘研判 | 15% | 新增 |

**输出**:

```python
{
  "fund_code": "005827",
  "action": "加仓",          # 加仓/减仓/持有/观望
  "confidence": 72,          # 置信度 0-100%
  "timing": "短期(1-2周)",   # 时机判断
  "signals": {
    "technical": {"score": 65, "reason": "净值突破20日均线"},
    "fundamental": {"score": 80, "reason": "规模稳定,经理评级5星"},
    "news": {"score": 75, "reason": "白酒板块利好消息集中"},
    "holdings": {"score": 70, "reason": "重仓股整体走强"},
    "market": {"score": 55, "reason": "大盘震荡偏多"}
  },
  "key_reasons": ["重仓白酒板块受消息面利好", "净值突破关键均线"],
  "risks": ["大盘震荡风险", "白酒板块估值偏高"]
}
```

**API 设计**:

```
GET  /api/fund/{fund_code}/advice       基金买卖建议(五信号)
GET  /api/fund/advice/list              建议列表(多基金)
POST /api/fund/{fund_code}/deep-analysis 深度分析(触发智能体辩论)
```

### 3.5 7智能体辩论(调整角色)

保留多空辩论框架,角色聚焦基金/板块/消息面:

| 智能体 | 立场 | 职责 |
|--------|------|------|
| 消息面分析师(新) | 多/空 | 解读消息面对基金影响 |
| 基金分析师(新) | 多/空 | 基金本身质地判断 |
| 板块分析师(新) | 多/空 | 重仓股板块趋势 |
| 技术分析师 | 中立 | 净值技术指标 |
| 基本面分析师 | 中立 | 重仓股基本面 |
| 风险分析师 | 空头 | 风险提示 |
| 宏观分析师 | 中立 | 大盘+国际环境 |

**辩论流程**:

```
多空辩论(消息面/基金/板块分析师分多空两派)
    → 风险辩论(风险分析师提出风险点)
    → 综合决议(技术/基本面/宏观分析师投票)
    → 输出:买卖建议 + 置信度 + 关键理由 + 风险
```

**API 设计**(沿用现有 `/api/agent/*`):

```
POST /api/agent/debate        触发智能体辩论
GET  /api/agent/debate/{id}   查询辩论结果
```

### 3.6 建议模板库(话术改造)

原24话术模板转为"建议输出模板":

- **变量**:基金名称/建议动作/置信度/关键理由/风险点/时机
- **模式**:
  - 静态模板(默认,<10ms,零成本)
  - AI生成(可选,2-5s,LLM调用)
- **故障降级**:AI生成失败 → 自动回退静态模板 + 日志告警

**API 设计**:

```
GET  /api/scripts/list               模板列表
GET  /api/scripts/{id}/render        静态渲染
POST /api/scripts/ai-generate        AI生成(可选)
```

## 6. 数据流设计

### 6.1 基金买卖建议生成流程

```
用户输入基金代码
    │
    ├─→ P1-1 消息面聚合引擎 → 消息面信号(25%)
    │       (新闻+公告+舆情+AI检索 → 去重分类 → LLM总结)
    │
    ├─→ P1-2 重仓股板块分析 → 重仓股信号(20%)
    │       (持仓查询 → 板块关联 → 集中度 → 净值影响预估)
    │
    ├─→ P1-3 大盘研判 → 大盘信号(15%)
    │       (指数+板块轮动+资金流+情绪 → 温度计)
    │
    ├─→ 技术面信号(20%) — 原有,基金净值趋势/均线
    │
    ├─→ 基本面信号(20%) — 原有,规模/经理/评级
    │
    └─→ P1-4 五信号融合 → 建议输出
            (加仓/减仓/持有/观望 + 置信度 + 时机 + 理由 + 风险)
```

### 6.2 智能体辩论流程(深度分析)

```
用户触发深度分析
    │
    ├─→ 收集五信号数据 + 消息面摘要
    │
    ├─→ 多空辩论(3轮)
    │   ├─ 消息面分析师(多 vs 空)
    │   ├─ 基金分析师(多 vs 空)
    │   └─ 板块分析师(多 vs 空)
    │
    ├─→ 风险辩论(1轮)
    │   └─ 风险分析师提出风险点,多空回应
    │
    ├─→ 综合决议
    │   └─ 技术/基本面/宏观分析师投票
    │
    └─→ 输出:买卖建议 + 置信度 + 关键理由 + 风险
```
