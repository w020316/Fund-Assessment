## 一、交付清单与文件职责

| 文件 | 职责 | 是否可直接用于生产 |
|---|---|---|
| `design-system/tokens.css` | 全部设计 token（色/字/间距/动效/层级）+ 字体资源 + 旧主题映射 | ✅ |
| `design-system/components.css` | 组件样式与三断点规则，只依赖 token | ✅ |
| `design-system/prototype.html` | 5 个核心业务页的可交互原型（含预览画布切换） | ❌ 仅原型 |
| `design-system/style-validation.html` | v0.1 风格验证页（色彩/字体/禁用规则的可视化证明） | ❌ 仅验证 |

**三层结构**（任何视觉元素必须归入其中一层，否则不允许存在）：

| 层 | 职责 | 元素 | 预算 |
|---|---|---|---|
| 底座层 | 空间与深度 | 深空底色、极细网格、静态光晕 | 不透明度 ≤8% |
| 信息层 | 承载全部可读内容 | 实底面板、玻璃面板、1px 发丝描边 | 正文对比度 ≥4.5:1 |
| 信号层 | 只表达状态与焦点 | 霓虹描边、焦点环、状态点、进度 | ≤5% 可视面积 |

**三条铁律**：光只描边不填内容 / 霓虹只标状态不承语义 / 动效只做反馈不做表演。

## 二、三步接入

```html
<!-- 1. 引入样式（顺序不可换：token 必须在组件之前） -->
<link rel="stylesheet" href="/design-system/tokens.css">
<link rel="stylesheet" href="/design-system/components.css">

<!-- 2. 在应用根容器上挂 .qf-ds（它同时是容器查询容器） -->
<div class="qf-ds qf-app"> … 应用内容 … </div>

<!-- 3. 复用组件类名，不再手写视觉样式 -->
<button class="qf-btn qf-btn--primary">开始分析</button>
```

**响应式契约（全系统唯一的结构性要求）**
`.qf-ds` 声明了 `container-type: inline-size`，组件断点写在 `@container qfapp` 内。
落地时**应用根容器宽度必须等于视口宽度**（`100%`），此时容器宽度与视口一一对应，断点行为与媒体查询完全一致。
若根容器被塞进侧栏或弹窗，断点将按容器宽度而非视口计算——这是唯一会"失效"的场景。

**为什么用容器查询而不是媒体查询**：同一套规则既能服务真实页面，也能服务原型里的"1440/1024/390 画布预览"，避免维护两套断点代码。

**兼容性**：Chrome 105+ / Safari 16+ / Firefox 110+。更低版本会退化为桌面布局（不报错，但无响应式）。

### 2.1 存量页面接入（已完成）

存量 `web/static/index.html`（约 7,300 行、已有大量经过实测的布局与 CLS 修复）**不改结构、不换类名**，通过 `web/static/css/aurora-theme.css` 接入：

| 做法 | 说明 |
|---|---|
| Token 覆盖 | 在 `body.hud-theme` 下重定义 `--bg-*` / `--text-*` / `--accent-*` / `--color-*` / `--hud-*`，存量规则自动继承新色板 |
| 组件视觉 | 用存量类名（`.card` / `.btn` / `.tab` / `.nav-item` / `table` …）重写外观与状态，不产生第二套 DOM |
| 断点 | 沿用存量已验证的布局断点（移动 ≤768 / 平板 769–1200 / 桌面 >1200），**只调视觉密度，不改布局结构** |
| 回退 | 移除 `body` 上的 `hud-theme` 类即整体失效，零污染 |
| 字体 | 新增 `font-src https://cdn.jsdelivr.net`（仅字体），`font-display:swap` 保证失败不阻塞 |

**双轨说明**：`components.css` 用容器查询（服务新页面与原型画布）；`aurora-theme.css` 用媒体查询（服务存量页面）。两者共用同一套 token 与同一组数值，不存在第二套设计规则。

**实测对照（Playwright，Chromium）**

| 指标 | 接入前 | 接入后 | 规范值 |
|---|---|---|---|
| 桌面顶栏 / 侧栏 / 边距 | 52 / 180 / 20 | **64 / 200 / 32** | 64 / 200 / 32 |
| 平板顶栏 / 侧栏 / 边距 | 52 / 60 / 20 | **60 / 60 / 24** | 60 / 176 / 24 ⚠ |
| 移动顶栏 / 底栏 / 边距 | 46 / 58 / 12 | **56 / 56 / 16** | 56 / 56 / 16 |
| 页面底色 / 卡片底色 | `#0A0E14` / `#111826` | **`#04070E` / `#0C131F`** | 同 |
| 主强调色 | `#22D3EE` | **`#22E3FF`** | 同 |
| 横向溢出 / 控制台错误 | 无 / 0 | **无 / 0** | — |

**已知偏差（如实记录，未掩盖）**
1. **平板侧栏**：存量在 769–1200 把侧栏折叠为 60px 图标轨（首屏信息量优先），与规范"平板 176px 全宽"不一致。这是存量经过实测的取舍，本轮不改布局，仅视觉收口；如需统一，应作为独立变更评估。
2. **768px 边界**：存量用 `max-width:768`（含 768）判为移动，规范为 `<768`。1px 边界差异，实际设备无影响。
3. **移动顶栏**：存量原为 46px，本轮提升到 56px 以满足规范，已实测无溢出、无控制台错误。
4. **字体**：CSP 原为 `default-src 'self'`，为加载展示字体新增 `font-src https://cdn.jsdelivr.net`；若后续自托管 woff2，应删除该条。

## 四、字体系统

### 4.1 字体族

| 角色 | 字体栈 | 使用边界 |
|---|---|---|
| 展示字 `--qf-font-display` | `Chakra Petch` → `Bahnschrift` → `DIN Alternate` | 只排**拉丁字母与阿拉伯数字**：标题、KPI 大数、全大写 micro 标签 |
| 正文字 `--qf-font-body` | `HarmonyOS Sans SC` → `PingFang SC` → `Source Han Sans SC` → `Microsoft YaHei` | 全部中文、正文、按钮文案 |
| 等宽字 `--qf-font-mono` | `JetBrains Mono` → `Cascadia Mono` → `Consolas` | 股票代码、ID、接口字段、坐标轴 |

> **红线**：展示字没有中文字形，用它排中文会触发浏览器合成粗体，出现糊字与字重失真。中文一律走正文栈。
> **数字**：所有数值必须 `font-variant-numeric: tabular-nums slashed-zero`，保证小数点对齐且 `0` 不混 `O`。

### 4.2 字阶（11 级，四要素齐全）

| Token 变量 | 字号/行高 | 字重 | 字间距 | 使用场景 |
|---|---|---|---|---|
| `--qf-t-display-1` | 56 / 64 | 700 | `-0.02em` | 品牌 Hero（桌面）；移动 34/40 |
| `--qf-t-display-2` | 40 / 48 | 700 | `-0.01em` | 页面主标题；移动 28/36 |
| `--qf-t-h1` | 32 / 40 | 700 | `-0.01em` | 模块大标题；移动 26/34 |
| `--qf-t-h2` | 24 / 32 | 600 | `0` | 页面/卡片组标题；移动 22/30 |
| `--qf-t-h3` | 20 / 28 | 600 | `0` | 卡片标题 |
| `--qf-t-h4` | 18 / 26 | 600 | `0` | 小节标题 |
| `--qf-t-body-l` | 16 / 24 | 400 | `0` | 长文正文 |
| `--qf-t-body` | 14 / 22 | 400 | `0` | 默认正文 |
| `--qf-t-body-s` | 13 / 20 | 400 | `0.01em` | 表格、紧凑列表 |
| `--qf-t-caption` | 12 / 16 | 500 | `0.04em` | 时间戳、单位、辅助 |
| `--qf-t-micro` | 11 / 16 | 600 | `0.08em` | 分类标签、角标（大写） |

## 五、间距、形状、阴影

`0 / 8 / 16 / 24 / 32 / 40 / 48 / 64 / 80 / 96`（`--qf-space-1 … --qf-space-12`）

**禁止** 13px / 18px / 22px 等非标值用于 margin/padding。

## 六、组件规范

> 每个组件给出：结构类名、尺寸、变体、状态、适用场景、禁用场景、无障碍要点。
> 所有类名以 `qf-` 开头，变体用 `--`，状态用 `.is-*`，语义状态用 `aria-*` 或 `[disabled]`。

### 6.1 Button 按钮

```html
<button class="qf-btn qf-btn--primary qf-btn--lg">开始分析</button>
<button class="qf-btn qf-btn--neon">组合建议</button>
<button class="qf-btn qf-btn--ghost qf-btn--sm">导出</button>
<button class="qf-btn qf-btn--danger">清空</button>
```

| 项 | 桌面 | 平板 | 移动 |
|---|---|---|---|
| 高度 | 40（sm 32 / lg 48） | 40 | 48（sm 40 / lg 52） |
| 水平内边距 | 20 | 20 | 16 |
| 字号 | 14（sm 13 / lg 15） | 14 | 15（sm 13 / lg 16） |
| 命中区 | ≥44×44（`::before` 扩展） | 同 | 同 |

**变体**：`--primary`（单屏仅 1 个主 CTA）/ `--neon`（次级主操作）/ `--ghost`（常规）/ `--danger`（破坏性）/ `--quiet`（弱化文本按钮）。
**状态**：hover（渐变位移 8% + 光晕）/ active（`scale(.98)`）/ focus-visible（双环）/ disabled（opacity .45 + `cursor:not-allowed`）/ loading（`qf-btn__spinner` + 宽度锁定，不跳动）。

**禁用**：① 同屏 ≥2 个 `--primary`；② 用按钮色表达涨跌（必须用 badge）；③ 省略 `--sm`/`--lg` 直接手写高度。

### 6.2 IconButton 图标按钮

`qf-icon-btn`，40×40（移动 48×48），命中区由 `::after` 扩到 44/48。必须有 `aria-label`。

**禁用**：无 `aria-label` 的纯图标按钮；把图标按钮当主操作使用（主操作必须带文字）。

### 6.3 Field 输入

```html
<div class="qf-field">
  <span class="qf-field__lead">⌕</span>
  <input class="qf-field__input" placeholder="搜索代码 / 名称">
  <span class="qf-field__trail">/</span>
</div>
```

| 项 | 桌面 | 平板 | 移动 |
|---|---|---|---|
| 高度 | 40 | 44 | 48 |
| 字号 | 14 | 14 | **16**（防 iOS 聚焦自动缩放） |
| 内边距 | 12 | 12 | 12 |

**状态**：`.is-invalid`（红边 + 3px 红光）/ `.is-valid`（绿边）/ `[data-disabled]`。
**必须配套**：`<label class="qf-label">` + `.qf-help`（错误时加 `.is-error`）。

**禁用**：仅用 placeholder 代替 label；错误状态只改颜色不写原因；移动端字号 <16px。

### 6.4 Switch 开关

`<button class="qf-switch" role="switch" aria-checked="true" aria-label="实时刷新">`
轨道 40×22（移动 44×24），命中区 `::before` 44×44。切换 240ms。

**禁用**：用 `checkbox` 伪装成开关却不加 `role="switch"`；开关直接触发不可逆操作（必须二次确认）。

### 6.5 Checkbox 复选

`<label class="qf-check"><input type="checkbox" checked><span class="qf-check__box"></span>文案</label>`
最小高度 44（移动 48），盒子 18（移动 20）。

**禁用**：无 label 包裹的自定义复选框（丢失点击区域与无障碍名称）。

### 6.6 Tabs 标签页

`qf-tabs` + `qf-tab[role=tab][aria-selected]`；高 32（移动 44 等分）。命中区上下扩展 6px。

**禁用**：标签超过 5 个仍用等分（应改为下拉或横向滚动）；用标签页承载不同数据源却无 loading 状态。

### 6.7 Badge 徽章

`qf-badge--up / --down / --warn / --info / --neon / --plain`，高 24（移动 28）。

**禁用**：仅靠徽章颜色表意（必须带 ▲▼⚠ 或文字）；徽章内放可点击元素。

### 6.8 Card / Glass 卡片

`qf-card`（padding 24/20/16）、`qf-card--interactive`（可点击）、`qf-card--flush`（表格容器）、`qf-glass`（玻璃，最多 1 层）。
结构：`qf-card__head` + `qf-card__title` + `qf-card__body`。

**禁用**：玻璃嵌套玻璃；在玻璃卡内放长文段落；卡片内出现 2 个以上强调色。

### 6.9 Table 表格

`qf-table-wrap`（横向滚动）+ `qf-table`；表头 40px sticky；行高 44（移动 52）；字号固定 13（**不随断点缩小**）。
数值列加 `qf-table__num`（右对齐 + tabular）。排序：`th[data-sort][aria-sort]`。

**禁用**：移动端压缩字号换取列宽（应横向滚动）；数值列截断；用横线代替斑马纹与 hover。

### 6.10 Nav / Tabbar 导航

- 桌面：`.qf-nav`（200px）+ `.qf-nav__item`（40px，命中区 44）。
- 平板：176px。
- 移动：`.qf-nav` 隐藏，`.qf-tabbar` 显示（56px + safe-area）。

状态用 `aria-current="page"`。**禁用**：移动端同时保留侧栏与底栏；导航项无当前态。

### 6.11 Progress / Ring 进度

`qf-progress` + `qf-progress__bar`（4px，移动 6px）；不确定进度用 `--indeterminate`。
`qf-ring` 用 `--qf-ring-value` 控制占比。

**禁用**：用进度条表达"数据缺失"（应使用空/错态）；确定进度却用无限循环动画。

### 6.12 Skeleton 骨架

`qf-skel` / `--line` / `--title` / `--block`。加载超过 300ms 才显示骨架；首屏容器必须预留高度防 CLS。

### 6.13 State 空 / 错 / 载

`qf-state`（`--error` / `--warn`）。必须含：图标 + 标题 + 原因 + 可选操作。
**铁律**：数据源失败必须 `--error` 并给出错误码与重试，**不得**渲染"暂无数据"。

### 6.14 Toast / Modal / Tooltip

- Toast：右下（移动顶部居中/全宽），进入 320ms、停留 4s、退出 200ms。
- Modal：桌面居中最宽 560，移动为底部抽屉（16px 顶角 + safe-area）。
- 必须支持 `Escape` 关闭；遮罩点击关闭；打开时焦点进入弹窗。

**禁用**：用 Toast 承载需要用户确认的决策；Modal 内再套 Modal。

### 6.15 Pager 分页

`qf-pager__btn`，32px（移动 40），命中区扩展 44。

## 七、视觉元素使用场景与禁用规则

### 7.1 霓虹渐变
- ✅ 品牌 Logo、Hero（单屏 1 处）、主 CTA、进度/选中指示、图表单一高亮系列。
- ❌ 正文背景、表格单元格、大面积容器底（>320×180 或 >15% 可视面积）、与玻璃叠加、同屏 2 个以上大面积渐变。

### 7.2 赛博朋克元素（扫描线/网格/角标/故障字）
- ✅ 品牌头图、页面转场（≤500ms）、加载态、空态插画、分节装饰。
- ❌ 数据表格、图表绘图区、表单标签、正文 3 行以上区域、数值单元格 120px 内。
- 扫描线不透明度 ≤0.06，网格 ≤0.035；**glitch 不得作用于任何可读文字**。

### 7.3 玻璃拟态
- ✅ 顶栏、浮层、导航、Hero 信息卡；**最多 1 层嵌套**（同屏 ≥3 处即超预算）。
- ❌ 长文阅读区底色、叠在流动光斑上、`backdrop-filter` >16px。
- 强制配套：1px 发丝描边 + 顶部内高光 + 不透明度 ≥0.55。

### 7.4 流动光效
- ✅ Hero 背景、空态、加载页、品牌转场。
- ❌ 表格/图表/表单内、无遮罩的文字背后、同屏 >1 处。
- 强制：仅 transform/opacity；周期 ≥6s；`prefers-reduced-motion` 与页面隐藏时暂停。

### 7.5 展示字体
- ✅ 拉丁标题、KPI 大数、大写 micro 标签。
- ❌ 中文正文、表格数字列、按钮中文文案。

### 7.6 十条硬性禁用组合

| # | 禁用组合 | 原因 |
|---|---|---|
| 1 | 霓虹大面积渐变 + 玻璃层 | 渐变被打散为噪点，对比不可控 |
| 2 | 流动光斑 + 正文文字（无遮罩） | 亮斑扫过时对比跌破 3:1 |
| 3 | 扫描线 + 数据表格/图表 | 干扰数值读取 |
| 4 | 霓虹色 + 涨跌/告警语义 | 语义色必须唯一 |
| 5 | 同屏 ≥2 个大面积渐变 | 视觉失去焦点，信号层超预算 |
| 6 | 玻璃层嵌套 >2 层 | 对比不可预测，性能骤降 |
| 7 | glitch/shake + 可读正文或数值 | 直接影响识别 |
| 8 | 装饰动效 + 交互动效（同一元素） | 反馈被淹没 |
| 9 | 展示字 + 中文正文/表格数字 | 合成粗体糊字 |
| 10 | 仅靠颜色 + 区分状态 | 色盲/强光失效（WCAG 1.4.1） |

## 八、动效规范

### 8.1 时长（交互动效硬约束 200–500ms）

| Token | 值 | 适用 |
|---|---|---|
| `--qf-dur-1` | 200ms | hover / press / focus |
| `--qf-dur-2` | 240ms | 开关、徽章、勾选 |
| `--qf-dur-3` | 320ms | 卡片展开、标签切换、抽屉 |
| `--qf-dur-4` | 420ms | 页面转场、Modal |
| `--qf-dur-5` | 500ms | 上限：全屏转场 |

**环境循环动效豁免**：光晕呼吸、骨架微光、流动光不属于交互动效，不受 200–500ms 约束，但必须仅在 transform/opacity 上运行、不覆盖可读文本、可被关闭。

### 8.2 缓动

`--qf-ease-standard` `cubic-bezier(.2,.8,.2,1)`（默认）/ `--qf-ease-enter` `(.16,1,.3,1)`（进入）/ `--qf-ease-exit` `(.4,0,1,1)`（离开）/ `--qf-ease-emphasis` `(.34,1.4,.64,1)`（仅 ≤24px 小元素，scale ≤1.04）。
**禁止**：`linear` 用于交互动效；`ease-in-out` 用于进入；>1.08 回弹。

### 8.3 分组件触发表

| 组件 | hover | press | focus | loading | 状态切换 |
|---|---|---|---|---|---|
| 主按钮 | 渐变位移 8% + 光晕 200ms | `scale(.98)` 200ms | 双环 200ms | 12px 转圈 + 宽度锁定 | 300ms |
| 幽灵/次级 | 描边变霓虹 + 底色 +4% 200ms | `scale(.98)` | 双环 | 同上 | 200ms |
| 输入 | 描边 line-2 200ms | — | 描边青 + 外发光 240ms | 右侧骨架条 | 错误 240ms 抖 2px（1 次） |
| 导航项 | 背景 + 左条展开 200ms | 背景加深 | 双环 | — | 240ms |
| 卡片 | 描边亮 + 上移 1px 200ms | `scale(.995)` | 双环 | 骨架微光 1.4s | — |
| 标签页 | 文字转主色 200ms | `scale(.98)` | 双环 | — | 320ms |
| 开关 | 亮度 +8% 200ms | 圆点 `scale(.92)` | 双环 | — | 240ms |
| Toast | — | — | — | — | 进 320 / 停 4s / 出 200 |
| Modal | — | — | 焦点入弹窗 | — | 遮罩 320 / 面板 320 |
| 页面转场 | — | — | — | — | 旧 200 出 / 新 320 入 |

**优先级铁律**：动效期间控件必须立即可再次响应，禁止 `pointer-events:none` 锁 500ms。

## 十二、扩展指南（保证"无需重构核心规则"）

新增一个组件只需三步：

1. **先找 token**：颜色、字号、间距、时长必须引用现有变量；找不到时先提 token，再写组件。
2. **套用模板**：结构（`__` 元素）+ 变体（`--`）+ 状态（`.is-*` / `aria-*`）+ 命中区扩展（若视觉 <44）。
3. **补断点**：在 `@container qfapp` 内追加移动/平板覆盖，沿用既有尺寸表，不发明新数值。

**不得**：在组件里写裸色值、裸像素、`!important` 覆盖 token、引入第二套断点。
**评审清单**：对比度、热区、动效时长、reduced-motion、禁用组合五条，缺一不合并。

## 十三、已知限制与下一步

| 限制 | 说明 | 下一步 |
|---|---|---|
| 容器查询兼容 | 低于 Chrome 105 / Safari 16 退化为桌面布局 | 若需支持旧版，增加 `@supports` 双轨媒体查询 |

| 字体自托管 | 当前用 CDN 兜底 | 生产改同域 `woff2`，去掉第三方依赖 |
| 图表 | 未定义图表组件（坐标轴/图例/配色顺序） | 下一轮补 `qf-chart` 规范 |
| 空/错态文案 | 仅给出结构，未统一文案模板 | 补文案规范（错误码 + 原因 + 动作） |

**建议的接入顺序**：先替换按钮/输入/表格/状态组件（收益最高、风险最低），再替换导航与弹窗，最后接入图表与新页面。每步都可独立回滚（移除 `qf-ds` 即失效）。
