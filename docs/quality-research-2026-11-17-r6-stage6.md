## 一、为什么要立项：本轮实测出来的三条"治理缺口"

| 缺口 | 本轮实证 | 根因层级 |
|---|---|---|
| **样本量 ≠ 总体** | 涨跌家数恒 `100/0/0`（接口单页上限 100，按涨幅降序取前 100）、板块轮动恒 100 分（`pz=50` 取前 50 个板块） | 取数层不知道"我拿到的不是全量" |

这三条的共同点：**错误数据不抛异常**。所以它们能活 5 个多月、跨过五轮评审。

**结论先行**：本项目需要的不是"再引入一个数据框架"，而是**一层很薄的「数据契约」**——每个字段上线时必须自带三样东西：① 单位与基准；② 与总体的一致性校验；③ 可比对的自证等式。外部项目能提供的是**设计参照**，不是依赖。

## 五、建议方案：不引入框架，建一层「数据契约」

### 5.1 三件套（每字段上线必须齐备）

```
① 单位与基准声明   unit="股" | "元" | "万元" | "小数(基准=收盘价)" | "百分数(基准=昨收)"
② 自证等式          金额/量/价 三者任取其二必须能算出第三个（写进测试 fixture）
③ 一致性校验        样本量/总体 ∈ [0.90,1.15]；与相邻指标不得矛盾（如 板块全涨 而 个股普跌）
```

本轮已落地的实例（可直接作为模板）：
- `RQYE / RQYL == SPJ` → 证明谁是元谁是股（`8f140d1`）
- `DEAL_AMT / DEAL_PRICE == DEAL_VOLUME`、`9.92/12.02−1 == PREMIUM_RATIO` → 单位与基准（`ef47905`）
- `(rise+fall+flat) / (clist_total − 北交所) ∈ [0.90,1.15]` → 样本完整性（`59376c1`）
- `板块涨幅占比 ≥0.95 且 个股涨幅占比 ≤0.40 → 判口径可疑` → 跨指标矛盾（`065e4ba`）

### 5.2 建议的模块结构（最小改动，不动存量调用）

```
src/core/data_contract.py          # 新增
  ├─ FieldSpec(unit, basis, equation=None, range=None)
  ├─ assert_unit_consistency(rows, specs)     # 返回 [(ok, msg)]，供测试与运行时共用
  ├─ assert_coverage(sample, total, lo=.90, hi=1.15)
  └─ cross_check(a_ratio, b_ratio, rule)      # 跨指标矛盾检测

src/core/data_source_v2.py         # 只在新增/改动报表处挂 FieldSpec
  （不重构现有函数签名——40+ 测试 patch 依赖公开函数名）
```

### 5.3 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| M1（1 次会话） | 建 `data_contract.py` + 单测；把本轮 4 个已有等式改写成 `FieldSpec` 声明 | 4 个等式在测试里由契约层断言，不再散落在各测试文件 |
| M2（2~3 次） | 把 8 个上游报表逐张接入（东财 6 张 + 腾讯/新浪各 1） | 每张报表至少 1 条自证等式 + 1 条覆盖率校验 |
| M3（1 次） | 运行时降级联动：契约校验失败 → `counts_available=False` / `quality_score` 降级 | 契约失败时**不可能**再产出 `data_quality=normal` |

## 六、结论

1. **不引入 OpenBB / qlib 作为依赖**：加权得分 2.75 / 2.65，且 OpenBB 已结业、qlib 数据集停用；本项目规模不需要它们。
2. **抄它们两个设计**：OpenBB 的「provider 注册 + 标准化 schema + 多出口」，qlib 的「**point-in-time 语义**」（我们的净值/财报数据同样存在"用了未来才披露的数据"的风险，本轮没查，列为下轮重点）。
3. **自建薄契约层**：加权 4.15，改动集中在一个新文件 + 8 处挂载点，不重构存量。
4. **本轮已把它从"建议"变成"已验证"**：4 条等式已在生产环境抓到 2 个 P1（温度误差 48.7 分、结论方向反转）。这不是纸面收益。
