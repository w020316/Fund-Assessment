## 5. 改进建议(共 7 条)

### 5.1 改进建议 1: 多智能体分析进度指示(对应痛点 A)

**问题**: 等待 20-60s 期间仅显示静态文案,用户无法判断进度。

**改进方案**:
- 在 loading 态显示分步进度(如"数据聚合中 → 7 分析师会诊中 → 多空辩论中 → 综合决议中")
- 使用 SSE(Server-Sent Events)或轮询 `/api/agent/fund_analyze/{task_id}` 获取实时进度
- 显示已等待时长(如"已等待 23s")

**预期效果**: 用户焦虑感降低 50%+,放弃率下降。

**实现难度**: 中(需后端支持任务进度查询,前端改用轮询)

**优先级**: P1

---

### 5.2 改进建议 2: 分析结果持久化与历史回看(对应痛点 B)

**问题**: 关闭模态框后分析结果丢失,需重新分析(20-60s)。

**改进方案**:
- 后端 `/api/agent/fund_analyze` 返回结果时同时写入 SQLite(已有 `decision_history` 表)
- 前端在基金列表行增加"查看上次分析"按钮,调用 `/api/agent/history?fund_code=XXX` 获取最近一次
- 模态框关闭时 toast 提示"分析已保存,可在历史中查看"

**预期效果**: 用户无需重复等待,提升回看效率。

**实现难度**: 低(后端已有决策历史表,前端增加入口)

**优先级**: P2

---

### 5.3 改进建议 3: 独立"消息面"页面(对应痛点 E)

**问题**: 智能检索入口位于基金页的消息面卡片内,功能聚合度低。

**改进方案**:
- 新增顶部导航项"消息面"(路由 `/news`),与"国际市场""数据监控"并列
- 将基金页的消息面卡片+智能检索整体迁移到新页面
- 基金页保留"消息面影响"摘要(只读),点击"查看详情"跳转到独立页

**预期效果**: 符合用户心智模型,功能聚合度提升。

**实现难度**: 中(需调整导航结构,迁移组件)

**优先级**: P1

---

### 5.4 改进建议 4: 全局按钮 loading 状态(对应痛点 G)

**问题**: 除 AI 分析按钮外,大部分按钮(如"刷新持仓""大盘温度""消息面")点击后无 loading 反馈。

**改进方案**:
- 将 `withLoading()` 函数应用到所有触发异步操作的按钮
- 优先处理: `loadFundData`/`loadMarketThermometer`/`loadNewsFeed`/`loadFundAdviceV2`/`loadGlobalData`/`loadGlobalOverview`

**预期效果**: 防止重复提交,提供即时反馈。

**实现难度**: 低(`withLoading()` 已实现,仅需批量应用)

**优先级**: P2

---

### 5.5 改进建议 5: 顶部指数栏错误状态(对应痛点 H)

**问题**: 顶部指数栏在 API 失败时永久显示"加载中...",误导用户。

**改进方案**:
- API 失败时显示"指数数据暂不可用" + 重试按钮
- 区分"首次加载"与"刷新失败"两种状态

**预期效果**: 用户能准确判断数据状态。

**实现难度**: 低(修改 `loadIndexData` 的空状态分支)

**优先级**: P2

---

### 5.6 改进建议 6: toast 持续时间分级(对应痛点 I)

**问题**: toast 统一 3s 自动消失,重要错误来不及阅读。

**改进方案**:
- info 类: 3s 自动消失
- success 类: 2s 自动消失(快速反馈)
- warning 类: 5s 自动消失
- error 类: 不自动消失,需用户手动关闭或显示"已复制错误详情"按钮

**预期效果**: 用户能完整阅读错误信息,降低支持成本。

**实现难度**: 低(修改 `showToast` 函数)

**优先级**: P3

---

### 5.7 改进建议 7: 移动端底部 tab 分组(对应痛点 J)

**问题**: 360px 下底部 10 个 tab 挤压严重,误触率高。

**改进方案**:
- 移动端底部 tab 仅显示 5 个高频项(行情/基金/分析/消息面/我的)
- 其余项收入"更多"抽屉(点击展开)
- 桌面端保持 10 项侧边栏不变

**预期效果**: 移动端误触率下降,核心功能触达更快。

**实现难度**: 中(需新增"更多"抽屉组件,修改响应式逻辑)

**优先级**: P3

## 6. 新功能建议(共 4 项)

### 6.1 新功能 1: 基金对比分析

**用户价值**: 用户经常需要在 2-3 只同类基金间做选择,当前需逐只分析后人工对比,效率低。

**功能描述**:
- 在基金列表增加多选框,支持勾选 2-3 只基金
- 点击"对比分析"按钮,调用 `/api/fund/compare` 新接口
- 展示对比表格: 五信号评分并列、重仓股重叠度、板块分布对比、近 30 日净值走势叠加图
- AI 总结: "基金 A 在消息面占优,基金 B 在重仓股板块更强,综合建议..."

**实现难度**: 中(后端需新增对比接口,前端需对比表格组件)

**优先级**: P2

---

### 6.2 新功能 2: 投资决策回测

**用户价值**: 用户希望验证系统建议的历史准确性,建立对系统的信任。

**功能描述**:
- 新增"决策回测"页面,展示过去 30/60/90 天系统给出的所有建议
- 对每条建议,标注"建议后 7/14/30 日实际涨跌幅"
- 计算建议命中率(如"加仓"建议中,7 日后实际涨幅 >0 的比例)
- 可视化: 命中率折线图 + 建议分布饼图

**实现难度**: 中(依赖 `decision_history` 表,需新增命中率计算逻辑)

**优先级**: P2

---

### 6.3 新功能 3: 基金经理画像

**用户价值**: 偏专业用户关注基金经理的投资风格与历史业绩,当前系统未展示。

**功能描述**:
- 在基金详情中新增"经理画像"卡片
- 数据源: akshare `fund_manager_em` 基金经理详情
- 展示: 经理姓名/任职年限/管理规模/历史业绩/投资风格(价值/成长/均衡)
- AI 总结: "该经理擅长消费板块,近 3 年年化收益 15%,最大回撤 8%"

**实现难度**: 低(数据源已有,前端新增卡片)

**优先级**: P3

---

### 6.4 新功能 4: 个性化预警推送

**用户价值**: 用户不希望时刻盯盘,但希望在关键事件(如持仓基金大跌 3%+、重仓股异动、消息面重大利好)时收到通知。

**功能描述**:
- 在"配置"页新增"预警规则"模块
- 支持规则: 持仓基金涨跌幅阈值、重仓股涨跌幅阈值、消息面情绪指数阈值、大盘温度计阈值
- 触发方式: 浏览器通知(Web Notification API)+ 邮件(可选)
- 后端定时任务(每 5 分钟)检查规则并触发

**实现难度**: 中(后端需定时任务+通知服务,前端需规则配置 UI)

**优先级**: P3

### C.1 改进概述

本次 P0 性能优化(commit d4bd679)在不调整 UI 的前提下,通过后端缓存与并行化显著改善了用户感知性能,直接影响 §2 用户旅程图中的关键等待痛点。

### C.2 痛点缓解对照

| 原痛点 | v1.0 状态 | v1.1 P0 改进后 | 缓解程度 |

| **痛点 A**: 多智能体分析等待 20-60s | 首次与重复均需等待 | 首次仍需 20-60s;**相同基金 5 分钟内重复分析立即返回(0ms)** | 部分(首次仍等待) |
